# 画面の作り直し案（2026-10-17、前田さんの指摘を受けて）

## 指摘

- ゼロから予定表を作れそうに見えない
- 新しい PDF を読ませる導線がない
- 新しいアカウント（〇〇部）を作る導線がない
- 特定のアカウントだけの PDF を出す導線がない
- 不親切で、発案者でも使いたくない

## 何が起きたか

作ったのは「取り込みパイプライン + 管理・閲覧画面」で、学校の追加・部の追加・PDF の投入はすべて設定ファイル（`schools/meiden.yaml`）とコマンド（`npm run import`）でやる前提だった。利用者の動線（作る → 取り込む → 直す → 共有する）が画面に無い。これは設計の順番の誤り。

## 残すもの / 作り直すもの

| 残す（画面の下にそのまま使う） | 作り直す |
|---|---|
| データモデル（ワークスペース > カレンダー > スロット > イベント > 版） | 画面の構成すべて（情報設計・導線・文言） |
| 取り込み（PDF→AI、シート、CSV）、正規化、版差分、ICS | 設定ファイル前提の運用 → 画面から全部できるように |
| Supabase のスキーマ・権限・共有トークン | 取り込みを画面から起動できる API（アップロード → 読み取り → 版） |

## 利用者の動線（この順に画面を作る）

| # | 動線 | 画面 | 操作 |
|---|---|---|---|
| 1 | 予定表を作る | **ホーム** | 「予定表を作る」→ 名前（例: 愛工大名電、〇〇家、営業部）を入れるだけ。空の月間表が開く。空の状態に「次にやること」を出す |
| 2 | カレンダーを足す | **カレンダーの追加** | 「＋ カレンダー」→ 名前・色・スロット（例: トップ/セカンド/朝練）→ 入れ方を選ぶ: ① 画面で直接書く ② PDF・写真をアップロード ③ Google シート/CSV の URL ④ テンプレのシートをもらう |
| 3 | PDF を読ませる | **取り込み** | ドラッグ&ドロップ → 読み取り中 → 結果を表で確認、その場で修正 → 「この版を反映」。2 回目以降は前の版との差分を色で見せてから反映 |
| 4 | 直接書く | **月間表のセル編集** | セルをクリックして入力。種類（練習/休み/大会…）と時刻はその場で。Excel の感覚で上下左右キーで移動 |
| 5 | 直す・見る | **月間表** | いまの表示切替・版切替・差分表示は残す。文言を平易に（「層」→「カレンダー」、「スロット」→「班」） |
| 6 | 共有・出力 | **共有・出力** | チェックしたカレンダーと班、期間を選ぶ → ① 閲覧リンク ② ICS（Google/iPhone に追加ボタン）③ PDF（月間表 / 週間 / 一覧、プレビューしてから保存） |
| 7 | 人を招く | **メンバー** | メールで招待。「このカレンダーのこの班だけ編集できる」をチェックで指定 |

## 進め方

1. まず **クリックできるモック（HTML）** を 1 日で作り、7 画面の動線を前田さんに触ってもらう。ここで直す。
2. 承認後、モックどおりに実装（5〜7 日）。既存の取り込み・DB はそのまま下に敷く。
3. 名電のデータは「取り込み」画面からやり直して、設定ファイル無しで同じ状態に戻せることを確認する（他校展開の確認を兼ねる）。

## モックの確定事項（2026-10-17 前田さん確認）

モック: https://claude.ai/artifact/694Ed352nHXtQKeyWKCYuc （`docs/mock/prototype.html`）

| 項目 | 決めたこと |
|---|---|
| 用語 | 層 → カレンダー、スロット → 班 |
| 画面 | 左に目次（チェック｜色｜名前｜件数｜⚙）、中央に月間表、右に作業パネル。PC 前提 |
| カレンダーの設定 | ⚙ と見出しの「＋班」から、名前・色・班の追加/改名/並び替え/削除。削除時は予定の移動先を聞く |
| マスの編集 | 内容・種類・終日・開始/終了（終了が空なら 2 時間後）・日付/終了日（日をまたぐ）・班（複数 = 横結合）・場所 |
| 日をまたぐ予定 | 1 件で保持。表と PDF では開始日「▸ 10/22まで（4日間）」、途中「2日目」、最終日「最終日」 |
| 班をまたぐ予定 | 1 件に複数の班。表と PDF では横結合の黄色いマス。ICS は班ごとのカレンダーに 1 件ずつ |
| 共有・出力 | カレンダー × 班 × 期間を選ぶ → 閲覧リンク / ICS（全体・班ごと）/ PDF。班のチェックが 3 つすべてに効く |
| PDF | 用紙の実寸比（A4 横/縦・A3 横）、月間表/週間/一覧、日付列は折り返さない、土日の行の色、日曜下の太線、カレンダー色の帯、時刻→内容→場所の 3 行、種類の色、空きマスの地模様、中身の高さで改ページ |
| 導線 | ホームの「はじめての方へ」→ サンプルで 6 手順の案内。右上「？ 使い方」に役割別の使い方例とよくある質問 |
| 公開の制御 | 予定ごとの「下書き」（先生だけに見え、リンク・ICS・PDF に出ない）。カレンダーごとの公開のしかた「自動 / 手動」。手動は「未公開の変更 N 件 → 公開する」で、公開前に変わる点を一覧し、通知文をコピーできる。公開の日時指定は実装で対応。「公開されている内容だけで見る」で生徒側の見え方を確認 |

## 実装前に決めた「出力の確実さ」の担保

| 出力 | 作り方 | 確認方法 |
|---|---|---|
| PDF | 画面と同じ HTML をサーバー側の Chromium で PDF にする（見た目が画面のプレビューと一致） | 名電の 3 か月分を A4 横/縦・A3 横で出し、ページ内に収まる・日付が切れない・結合セルが正しいことを目視と自動テスト（行数・ページ数）で確認 |
| ICS | RFC 5545 準拠。期間イベント、終日、TRANSP、UID 固定、班ごとのフィード | Google カレンダーと iPhone に実際に購読して表示を確認。更新が反映されることを 1 件変えて確認 |
| 閲覧リンク | トークン + 範囲（カレンダー・班・期間） | 範囲外が見えないことをテスト |
