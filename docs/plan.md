# bukatsu-schedule 計画 v3（2026-10-17・**承認済み**）

## 前提（2026-10-17 に前田さんから）

| # | 前提 | 計画への反映 |
|---|---|---|
| 1 | **名電専用ではなく、他校の関係者も使える形（テンプレート化 or ソフトウェア化）にする** | 学校ごとの「ワークスペース」に予定源を層（レイヤー）として重ねる汎用構造。名電は 1 校目 |
| 2 | 学校予定は **PDF** で持っている | 学校予定の取り込みも PDF → AI 読み取り。PDF 読み取りを MVP に入れる |
| 3 | 運用アカウントは **ARCA** | Google カレンダー・配信・DB は ARCA 所有。学校側にアカウント作成や権限付与を求めない |
| 4 | 陸上部は **コピーのシート**でテスト | 元シート共有は本番時に。コピー（9/29 時点）で開発・試験 |
| 5 | 「業後」は **2 時間**、放課後開始は **15:30** | 終了不明の練習は既定 120 分。業後 = 15:30〜17:30、9 時 → 09:00〜11:00 |
| 6 | API キーは必要時に提示。それまでは **叩いたテイ（モック）** | AI 読み取りはモードを持つ。`mock` = 記録済みの読み取り結果を返す、`live` = Claude API。キー提示後に切替・再記録 |
| 7 | 先生は他の予定（競技団体・学校関係）との調整が不可欠。**入力できる、層の表示/非表示を選べる、版の前後差が分かる表示** | 「先生の手入力」層と「外部予定」層を持つ。表示切替と差分モードは中核機能 |

## 結論

- **形は Web アプリ（ソフトウェア化）**。学校ごとに、学校予定（PDF）、各部の予定（シート直読み／PDF／テンプレ入力）、外部予定（競技団体など）、先生の手入力、を層として重ね、表示/非表示・版差分表示・配布用月間表の印刷・Google カレンダー/ICS 配信を提供する。
- Google スプレッドシートのテンプレは **入力口の 1 つ**として残す（部はシートで作り続ける）。Apps Script を各校に配る方式は他校展開・差分表示・権限で行き詰まるため中核にしない。
- **既存の予定表は捨てさせない**。取り込む。先生が足すのは「他の予定」と調整事項だけ。
- **MVP は名電で層 5 つ**: 学校予定（PDF）、陸上（シート）、フェンシング（CSV）、サッカー（PDF、版差分のデモ）、先生の手入力。約 15 稼働日 + 試験運用 2 週間。
- **他校追加は設定だけ**（コード変更なし）を MVP の合格条件にする。
- Bekuta は部ごとの `all.ics` を読むだけ（副産物）。

### 2.1 比較表（前提 1・7 を基準に再評価）

| (b) Excel テンプレ + 変換 | △ | ○ | × | × | ○ | ○ | 中 | △ 手渡し | 不採用 |
| **(c) Web アプリ** | ◎ 設定で追加 | ○ | ◎ | ◎ | ○ 印刷 CSS → PDF | ◎ | 大 | ○ ARCA で一元 | **採用（本線）** |

### 2.2 全体像

```
取り込み（層ごと）                          表示・編集（Web）                     出力
├ 学校予定: PDF → AI 読み取り ──┐          ├ 月間表（日 × 層 / 日 × カテゴリ）     ├ 配布用の月間表（印刷 / PDF）
├ 部予定: シート直読み（陸上型）─┤  正規化  ├ 層の表示/非表示（人ごとに保存）        ├ Google カレンダー（ARCA 所有、層・カテゴリ別）
├ 部予定: CSV（フェンシング型）─┼─ 版管理 ─┤ 差分モード（追加・削除・変更を前→後で）├ ICS URL（層・カテゴリ別、秘密トークン）
├ 部予定: PDF → AI（サッカー型）┤  差分計算 ├ 先生の手入力（外部予定・調整事項）     ├ 変更一覧（通知文の下書き）
├ 外部予定: 手入力 / ICS 取り込み┤          └ 閲覧 URL（生徒・保護者、ログイン不要）  └ all.ics（Bekuta 用、副産物）
└ 部予定: テンプレ入力（新規の部）┘
```

| 要素 | 決定 | 補足 |
|---|---|---|
| 認証 | 先生はメールのマジックリンク。生徒・保護者はログイン不要の閲覧 URL + ICS | 学校側にアカウント管理を求めない |
| AI 読み取り | きれいな表は Haiku 4.5、PDF・写真は Sonnet 5.5。`mock` / `live` の 2 モード | `mock` は `fixtures/ai-responses/` の記録を返す。キー提示後に `live` で再記録して差分を確認 |
| 読み取り後の確認 | AI 読みは必ず「確認待ち」状態で入り、ARCA（または先生）が承認して版になる | 1 枚 145 行。確認画面は差分モードと同じ UI |
| スタック | TypeScript。Supabase（Postgres・Auth・Storage。Bekuta と同じ）+ Cloudflare Pages（画面）+ 取り込みは Node CLI（定期実行は後で Cron 化） | 開発はローカル Supabase（Docker）。クラウドの新規プロジェクトは月 10 ドルの見積もり（前田さんの org）。作成は承認後 |
| 配信 | Google カレンダーへ直接書き込み → そのカレンダーの ICS アドレスを iOS・Bekuta が購読 | 外部 ICS だけだと Google 側の再取得が半日〜1 日で制御不能。直書きなら Google 利用者は即時 |

## 3. 共通データモデル

### 3.1 構造

| 実体 | 主な項目 | 説明 |
|---|---|---|
| school | id, name, 設定（放課後開始時刻 = 15:30、既定練習時間 = 120 分、年度開始月） | 学校ワークスペース |
| layer | school, type（`school` / `club` / `external` / `manual`）, name, color, default_visible | 表示/非表示の単位。部は 1 層 + カテゴリ |
| source | layer, kind（`pdf` / `gsheet` / `csv` / `ics` / `template` / `manual`）, config | config = 取得先 URL、列の対応（日付列・時刻列・イベント列）、**読まない列**、カテゴリ別名、種類の判定語 |
| source_version | source, label（PDF の版番号 / 取得日時）, imported_at, file_hash, ai_model, status（確認待ち / 承認 / 却下） | 版 |
| event | 下表 | 1 日 × 1 層 × 1 カテゴリ × 1 種類 = 1 行 |
| event_change | version_from, version_to, event_uid, change（added / removed / changed）, before, after | 差分モードと変更一覧の元 |
| visibility | user, layer, visible | 人ごとの表示設定 |

### 3.2 イベント

| 項目 | 型 | 説明 | 例 |
|---|---|---|---|
| uid | ハッシュ | `(school, layer, category, date, kind)` で固定。版をまたいで同一 | |
| date / end_date | YYYY-MM-DD | 連続する休止・考査は 1 件に畳む | 2026-11-30 / 2026-12-03 |
| category | 文字列 | 部内の班。無ければ `全体`。学校予定は対象（`全校` `高2`） | トップ, 朝練 |
| kind | 列挙 | 部: `practice` `match` `competition` `off` `self` `pause:test` `pause:holiday` `event` `unknown`。学校: `class` `no_class` `exam` `school_event` `holiday`。外部: `external_event` | exam |
| time_start / time_end | HH:MM 任意 | 無ければ終日。終了不明は既定 120 分 | 16:15 / 18:15 |
| place, title, note | 文字列 | 件名に人名を入れない | 神領 / 練習 16:15 バス出発 |
| source_version, source_ref | 参照 | 出どころとセル位置 | `2026!C215`, `pdf#row5col4` |
| confidence | 0〜1 任意 | AI 読みのみ | 0.9 |

### 3.3 出力の表現

| 論点 | 決定 |
|---|---|
| カレンダーの単位 | 層ごと（学校予定、部 全体、部 カテゴリ、外部）。部のカレンダーに学校予定は含めず、購読者が重ねる |
| Bekuta 用 | 部ごとに学校予定込みの `all.ics` を別途生成 |
| プロパティ | `CATEGORIES:<カテゴリ>,<種類ラベル>` + `X-BUKATSU-LAYER` `X-BUKATSU-KIND` `X-BUKATSU-CATEGORY` `X-BUKATSU-VERSION` |
| 終日 / 時刻 | 練習・試合で時刻あり → 時刻。休み・休止・考査 → 終日 + `TRANSP:TRANSPARENT` |
| 差分モード | 追加 = 緑、削除 = 取消線、変更 = 「前 → 後」を同じセルに。版の選択は任意の 2 版 |
| 配布用の月間表 | 日 × 層（学校予定列 + 部のカテゴリ列）。脚注に版番号と変更一覧。陸上式（1 日 1 行）とサッカー式（日 × カテゴリ列）の 2 レイアウト |
| 個人情報 | 件名・説明に人名を入れない。source.config の「読まない列」を必須に。AI には人名を出力しない指示 + 出力後に姓名パターン検査 |

## 付録 B. 追加の要件（2026-10-17 前田さん）

- Bekuta と接続しやすく、かつ **Bekuta を使わなくても単体で成り立つ**ツールにする。
- 学校に限らず、**同僚・家族・恋人など特定の相手に特定の予定を共有しやすい**こと。
- **カレンダーごと丸ごとコピー**も、**特定の予定だけコピペ**も容易にする。
- **チェックしたカレンダーと期間を指定したら、必要な形で PDF に出力**できる。

### いまの設計との対応

| 要件 | 対応する部品 | 追加で要るもの |
|---|---|---|
| 単体で成り立つ | 出力は ICS / Google カレンダー / PDF。Bekuta は読む側 | なし（設計どおり） |
| 特定の相手に特定の予定を共有 | `share_links`（層・カテゴリで範囲を絞った閲覧 URL / ICS URL） | 範囲に **期間** と **個別イベントの選択** を追加。画面に「選んで共有リンクを作る」ボタン |
| カレンダーごと丸ごとコピー | 層ごとの ICS 書き出し（済） | 「自分のワークスペースに複製」（層のフォーク。元の版が更新されても自分の複製は独立） |

### 方針
設計は汎用（ワークスペース > カレンダー（層）> イベント）に寄せ、最初の利用者は学校のまま。学校固有なのは取り込みアダプタと設定ファイルだけにする。
