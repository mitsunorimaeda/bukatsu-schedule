# データの扱い（どこに・何を・誰が・いつまで）

予定表は学校の内部情報です。このアプリが何を、どこに、誰が見られる形で置いているかを書きます。アプリ内の「データの扱い」（一覧画面の右上、予定表の中では「データ」）にも同じ内容を出しています。

## 保存場所

| もの | 場所 |
|---|---|
| 予定のデータ（下記） | 運営（ARCA）が管理する Supabase のデータベース（AWS 東京リージョン、専用スキーマ `bukatsu`） |
| アプリ本体、閲覧リンク・ICS の配信、取り込み API | Cloudflare Pages / Pages Functions。アクセスログ（接続元など）が Cloudflare 側に短期間残る |
| 取り込みに使った PDF・画像 | **保存しない**。取り込み API がメモリ上で Claude API に渡し、読み取りが終わると捨てる。残るのは読み取った予定だけ |

## 保存するもの・しないもの

保存する: 予定表の名前と設定、カレンダーと班、予定（内容・日時・場所・備考・下書きかどうか）、取り込みの版と差分、メンバーのメールアドレスと権限、閲覧リンク（トークンと範囲）。

保存しない: **生徒の名前・連絡先**。入力欄にも読み取りにも生徒名を扱う場所はなく、PDF に書いてあっても予定には取り込みません（取り込みの指示書 `packages/core/src/ai/prompts.ts` で生徒名を除外）。顧問など大人の名前は予定の一部として残ることがあります。

## 誰が見られるか

- メンバーは、権限（管理者・先生・閲覧）とカレンダー・班ごとの編集権の範囲で。データベース側の RLS で強制しています（`supabase/migrations/`）。
- 閲覧リンク・ICS の URL を知っている人は、そのリンクに含めたカレンダー・班・期間の**公開済みの予定だけ**。下書きと確認待ちの取り込みは出ません。リンクは「共有・出力」からいつでも無効にできます。
- 運営（ARCA）は、障害対応や不具合の調査のためにデータベースに触れる立場にあります。それ以外の目的で予定の内容を見たり、他に渡したりしません。

## AI に送るもの

- 「PDF・シートを取り込む」で PDF や画像を読ませたときだけ、そのファイルの内容を Anthropic の Claude API に送ります。API に送ったデータはモデルの学習には使われません（Anthropic の商用 API の規約）。
- 「自分の AI に読ませて貼り付ける」を選んだときは、PDF はこのアプリではなく、あなたが選んだ AI サービス（OpenAI・Google・Anthropic など）に、そのサービスの規約のもとで送られます。無料プランは入力を学習に使う設定が既定の場合があるので、設定で切るか学校・職場のアカウントを使ってください。このアプリには貼り付けた結果（予定の JSON）だけが届きます。
- 手入力の予定、Google シート・CSV からの読み取り、閲覧・共有の操作では AI に何も送りません。

Google シート / CSV をつないだ場合、登録した URL の CSV はサーバー（Cloudflare の関数）が取りに行って画面に渡します。自動更新を有効にしたカレンダーは、サーバーが 1 時間ごとに同じ URL を見に行きます。保存されるのは画面で選んだ列（日付・時刻・内容・場所・班・終了日）から作った予定だけで、選ばなかった列（選手名など）と CSV そのものは保存しません。

## いつまで残るか

- 消すまで。カレンダーの削除や「予定表を全削除」で、その場でデータベースから消えます（RPC `delete_workspace`、管理者のみ）。
- データベースの自動バックアップには、消したあとも一定期間（Supabase の設定で通常 7 日）残り、その後なくなります。
- ログインのアカウントは予定表と別に管理されています。全削除してもアカウントは残ります。アカウント自体の削除は運営に連絡してください。

## 持ち出す

予定表の「データ」から、ブラウザの中で作って保存します（サーバーに何も送りません）。

| 形式 | 中身 | 使い道 |
|---|---|---|
| JSON | 設定・カレンダー・班・予定（下書き含む）・公開中の内容 | 別の環境に移す元データ |
| CSV | 1 行 1 予定（BOM 付き） | Excel・Google シート |
| ICS | 公開中の予定を 1 ファイルに | Google カレンダー等に「ファイルから取り込み」 |

## 自分で立てて使う（データも AI の鍵も自分の管理下に）

このアプリは Supabase のプロジェクト 1 つと Cloudflare Pages 1 つで動きます。学校や自治体のアカウントで同じものを立てれば、ARCA には何も渡りません。

1. Supabase でプロジェクトを作り、`supabase/migrations/` を順に適用（専用スキーマ `bukatsu` だけを作ります）。PostgREST の公開スキーマに `bukatsu` を加える（`alter role authenticator set pgrst.db_schemas = 'public, graphql_public, bukatsu'`）。
2. Cloudflare Pages に `apps/web` をデプロイ（`npm run build` → `wrangler pages deploy dist`）。環境変数は `.env.example` の通り: Supabase の URL と公開鍵（ビルド時）、service role と Anthropic の API キー（Functions の secret）。
3. Supabase Auth の Redirect URL に自分の Pages の URL を登録。

README と `docs/status.md` に手順の詳細があります。
